## 1. 优化目标

V2 的核心目标不是增加更多页面或昂贵内容，而是让孩子愿意持续玩、确实记住词语，同时保持操作简单、反馈温和、成本可控。

优先级原则：

1. 先提升核心玩法与学习反馈，再增加内容量。
2. 文字、动效、声音和已有场景优先；图片不是每次练习的必需反馈。
3. 图片如需使用，优先离线批量生成、审核、复用，不在游戏过程中按次生成。
4. 不使用倒计时、生命值、失败惩罚、排行榜等制造压力。
5. 所有改动必须适配 iPad 横屏，并兼容已有本地存档。

## 3. 下一阶段建议

### P3：持续游玩的动力与变化感

目标：让孩子在不增加学习压力的前提下，更愿意连续完成一局并在以后回来。

建议范围：

- 关内短任务变化：例如“帮小狐狸找回 6 样东西”，沿用现有场景节拍，不新增第二套玩法。
- 伙伴反馈升级：根据首次遇见、连续答对、需要提示、完成复习给出不同短句。
- 阶段性收集：完成若干关后解锁可复用的称号、印章或场景小物；使用 CSS/SVG 或预生成资源。
- 复玩变化：同一关再次游玩时更换任务文案、词对组合和场景节奏，但不增加随机难度惩罚。
- 家长可理解的轻量周总结：只展示练过、待巩固、已经熟悉的词数，不做排名或复杂图表。

P3 开始前必须先完成一个 1024×768 横屏交互原型，并由用户选择方案后再开发。

### P4：内容扩展与质量体系

目标：在玩法稳定后扩展课程内容，并保证每批内容质量可验证。

- 扩展学期、年级或教材版本。
- 建立词对查重、格式、生字覆盖和难度校验。
- 为关卡补充人工审核的任务文案与复用场景资源。
- 如确有图片价值，使用 Gemini Image 离线全量生成、人工验收后随版本发布；不接入运行时逐次生图。

### P5：发布与长期维护

- 自动化回归测试纳入发布流程。
- 存档迁移与回退方案持续维护。
- 性能、离线可用性、触控与无障碍优化。
- 根据真实儿童试玩记录决定后续功能，不以功能数量作为完成标准。

## 4. 当前不做

- 运行时或每次配对后生成图片。
- 复杂间隔重复算法、账号系统和云端同步。
- 排行榜、连续签到压力、生命值、倒计时或红色失败页。
- 未经人工审核的自动无限关卡。
- 与学习目标无关的第二套小游戏。

## 5. 阶段验收标准

每个阶段只有同时满足以下条件才能标记完成：

- 产品规格和实施计划已经记录。
- 关键流程有自动化测试，旧功能无回归。
- TypeScript 与生产构建通过。
- 1024×768 iPad 横屏完成视觉与交互检查。
- 用户实际测试并明确确认通过。
- 代码已合并并推送 V2 `main`。
- [`project-progress.md`](./project-progress.md) 已同步更新。

## 6. 文档更新规则

以后每次发生以下事件，都必须更新项目进度文档：

- 一个 P 阶段开始：记录目标、范围、分支和验收标准。
- 方案确定：记录用户选择和被放弃的主要方案。
- 阶段开发完成：记录实现结果、测试结果和待验收项。
- 用户验收：更新为“已验收”。
- 合并或发布：记录分支、远程仓库、提交号和日期。
- 发现延期、阻塞或范围调整：记录原因和下一步，不隐去未完成项。

进度状态统一使用：`计划中`、`开发中`、`待验收`、`已完成`、`已暂停`。
